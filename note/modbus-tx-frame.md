# Modbus TCP TX/RX 프레임 읽는 법

mesclient의 Event Log(툴바 **Traffic** 체크)에 표시되는 `Modbus TX` / `Modbus RX` 줄을 해석하는 방법이다.

## 1. TX / RX 의미

| 표기 | 의미 | 방향 |
|---|---|---|
| `Modbus TX` | **Transmit(송신)**. mesclient가 슬레이브로 보낸 요청 | mesclient → mes |
| `Modbus RX` | **Receive(수신)**. mesclient가 슬레이브에게서 받은 응답 | mes → mesclient |

- 기준은 로그를 남기는 쪽(mesclient)이다.
- 슬레이브(mes) 입장에서는 방향이 반대다. mesclient의 TX가 슬레이브의 RX이고, 슬레이브의 응답이 슬레이브의 TX이다.

## 2. 프레임 구조

Modbus TCP 프레임은 **MBAP 헤더 7바이트 + PDU** 로 이루어진다.

```
[ MBAP 헤더 (7바이트) ]                      [ PDU ]
 TxID(2) | ProtoID(2) | Length(2) | UnitID(1) | FC(1) | 데이터...
```

| 필드 | 크기 | 설명 |
|---|---|---|
| Transaction ID | 2 | 요청/응답을 짝짓는 번호. 응답은 요청과 같은 값으로 돌아와야 한다 |
| Protocol ID | 2 | Modbus는 항상 `00 00` |
| Length | 2 | 이 필드 **뒤**의 바이트 수 (Unit ID + PDU) |
| Unit ID | 1 | 슬레이브 번호 (기본 `01`) |
| FC (기능코드) | 1 | 요청 종류 |
| 데이터 | 가변 | 기능코드별 내용 |

### 필드 크기 규칙

- **MBAP 헤더 7바이트는 무조건 고정** — Transaction ID, Protocol ID, Length, Unit ID 크기는 항상 같다.
- **기능 코드 1바이트 고정** — PDU 첫 바이트는 항상 기능 코드.
- **PDU 데이터는 기능 코드마다 명세에 정해진 고정 구조** — 아래 표 참고.

| 기능 코드 | 요청 데이터 구조 |
|---|---|
| FC 01 / 02 / 03 / 04 (읽기) | 시작 주소(2) + Quantity(2) |
| FC 05 (Coil 1개 쓰기) | 주소(2) + 값(2) |
| FC 06 (레지스터 1개 쓰기) | 주소(2) + 값(2) |
| FC 0F (Coil 여러 개 쓰기) | 시작(2) + 개수(2) + 바이트수(1) + 값들 |
| FC 10 (레지스터 여러 개 쓰기) | 시작(2) + 개수(2) + 바이트수(1) + 값들 |

## 3. 읽기 요청 (FC01 / FC03) TX 예시

Holding 전체 읽기 (기본 태그 기준):

```
00 01 00 00 00 06 01 03 00 00 00 3E
```

| 바이트 | 값 | 의미 |
|---|---|---|
| `00 01` | 1 | Transaction ID |
| `00 00` | 0 | Protocol ID |
| `00 06` | 6 | 이후 6바이트 (Unit 1 + FC 1 + 시작 2 + 개수 2) |
| `01` | 1 | Unit ID |
| `03` | 3 | 기능코드: Read Holding Registers |
| `00 00` | 0 | 시작 offset = `400001` |
| `00 3E` | 62 | 읽을 레지스터 개수 |

Coil 읽기 (기본 태그 기준, 요청 2개):

```
.. 01 01 00 00 00 0C     ← Coil offset 0부터 12개 (000001~000012)
.. 01 01 03 E7 00 01     ← Coil offset 999부터 1개 (001000)
```

## 4. 쓰기 요청 TX 예시

| 기능코드 | 용도 | PDU 형식 |
|---|---|---|
| `05` | Coil 1개 쓰기 | `05` + offset(2) + 값(2). ON = `FF 00`, OFF = `00 00` |
| `06` | 레지스터 1개 쓰기 | `06` + offset(2) + 값(2) |
| `10` | 레지스터 여러 개 쓰기 | `10` + 시작(2) + 개수(2) + 바이트수(1) + 값들 |

예) `DataCmd (000007)` 를 ON:

```
.. 00 06 01 05 00 06 FF 00
```

예) `OkWorkCounter (400003)` 에 `100000` (`0x000186A0`) 쓰기, ABCD 순서:

```
.. 00 0B 01 10 00 02 00 02 04 00 01 86 A0
```

`00 02`(시작 offset 2) `00 02`(레지스터 2개) `04`(데이터 4바이트) `00 01`(상위 워드) `86 A0`(하위 워드).

## 5. RX 응답 읽는 법

정상 응답 (Holding 읽기):

```
00 01 00 00 00 7F 01 03 7C ...(124바이트)
```

| 바이트 | 의미 |
|---|---|
| `00 01` | 요청과 **같은** Transaction ID (다르면 오류) |
| `00 7F` | 이후 127바이트 |
| `03` | 요청과 같은 기능코드 |
| `7C` | 데이터 바이트 수 (124 = 62 × 2) |
| 나머지 | 레지스터 값들 (각 2바이트, big-endian) |

쓰기 응답은 요청 앞부분을 그대로 되돌려 주는(echo) 형태다.

## 6. 예외 응답

기능코드에 `0x80` 이 더해져서 오고, 뒤에 예외코드 1바이트가 붙는다.

```
00 01 00 00 00 03 01 83 02
```

| 바이트 | 의미 |
|---|---|
| `83` | `03` + `80` = Holding 읽기 실패 |
| `02` | 예외코드 |

| 예외코드 | 이름 | 이 프로젝트에서 나오는 경우 |
|---|---|---|
| `01` | Illegal Function | 슬레이브가 지원하지 않는 기능코드 (FC02, FC04 등) |
| `02` | Illegal Data Address | 범위 밖 주소, 쓰기 허용되지 않은 Coil |
| `03` | Illegal Data Value | 개수/값이 규격을 벗어남 |
| `04` | Slave Device Failure | 슬레이브 내부 오류 |

## 7. 이 프로젝트에서 자주 보는 값

| 값 | 의미 |
|---|---|
| 요청 간격 | Scan Rate (기본 500ms) 마다 TX 3개 |
| 한 주기 요청 수 | FC03 1번 + FC01 2번 (기본 태그 기준) |
| 응답이 없을 때 | Unit ID 불일치. 슬레이브는 다른 Unit에 응답하지 않는다 (시나리오 1-8) |

관련 문서: `mes-client-test-scenarios.md` (시나리오 3번: 주소 표기 검증)

## 8. 최종 패킷 구조 정리 (현재 코드 기준)

### KEPServerEX → 내 앱 (요청)

**공통 MBAP 헤더 (7바이트 고정)**
```
TxID(2) | ProtoID(2)=0000 | Length(2) | UnitID(1)
```

**FC 01 — Coil 읽기**
```
MBAP | 01 | 시작주소(2) | Quantity(2)
```

**FC 03 — Holding Register 읽기**
```
MBAP | 03 | 시작주소(2) | Quantity(2)
```

**FC 05 — Coil 1개 쓰기**
```
MBAP | 05 | 코일주소(2) | 값(2)   ON=FF00, OFF=0000
```

**FC 06 — Holding Register 1개 쓰기**
```
MBAP | 06 | 주소(2) | 값(2)
```

**FC 10 — Holding Register 여러 개 쓰기**
```
MBAP | 10 | 시작주소(2) | 개수(2) | 바이트수(1) | 값들(개수×2)
```

---

### 내 앱 → KEPServerEX (응답)

**FC 01 — Coil 읽기 응답**
```
MBAP | 01 | 바이트수(1) | Coil데이터(⌈Quantity/8⌉바이트)
```
- Coil 8개씩 1바이트로 압축, LSB first

**FC 03 — Holding Register 읽기 응답**
```
MBAP | 03 | 바이트수(1) | 레지스터값들(Quantity×2)
```
- 레지스터 1개당 2바이트, big-endian

**FC 05 — Coil 쓰기 응답**
```
MBAP | 05 | 코일주소(2) | 값(2)   ← 요청 그대로 echo
```

**FC 06 — 레지스터 1개 쓰기 응답**
```
MBAP | 06 | 주소(2) | 값(2)   ← 요청 그대로 echo
```

**FC 10 — 레지스터 여러 개 쓰기 응답**
```
MBAP | 10 | 시작주소(2) | 개수(2)   ← 헤더 부분만 echo (데이터 제외)
```

**에러 응답 (공통)**
```
MBAP | FC|0x80(1) | 예외코드(1)
```
- `FC | 0x80`: 요청 기능코드에 최상위 비트를 켜서 에러임을 표시
